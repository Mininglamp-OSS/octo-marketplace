# PR #142：生命周期、旧客户端安装兼容与上线操作

本次仅交付三个行为：曾发布且无保护引用的 Skill/Expert 可删除；沿用 private
引用权限；新旧安装入口共用安装流程。不是整套 v2 决策文档的全部实现。

## 1. 现在的行为

| 场景 | 结果与原因 |
| --- | --- |
| 曾发布、已下架但无引用 | 可以软删除；版本、正式发布证据和审计记录保留。 |
| 有存活来源的编辑引用、当前发布引用，或 Team→旧 Expert 版本→Skill 引用 | 拒绝删除；下架不会自动解除引用。只有不再使用的纯历史版本不形成永久删除锁。 |
| private Expert→private Skill、private Team→private Expert | 同 owner、同 Space 时合法；space/system 来源、不同 owner 或跨 Space 均不可引用。独立引用开关开启或关闭时，创建、更新和发布均检查此规则；旧数据格式安装也沿用这一来源受众检查。已有容器内嵌副本保留原有归属校验。 |
| 旧 `POST /api/v1/plugins/install` | 保留 `plugin_id/workspace_id/runtime_id/custom_env` 请求体及 `agent_id/squad_id` 响应。旧式非 UUID runtime 仍由 Fleet 校验；不新增必填头。可选 `Idempotency-Key`；沿用旧身份接入，最终工作区/runtime 权限由 Fleet 校验。 |
| 新 `POST /api/v1/plugins/{plugin_id}/installations` | 保留必填 `X-Workspace-ID`、`Idempotency-Key` 及 runtime UUID；支持可选资源名称。 |

两条 URL 对同一资源、工作区、runtime、环境变量发出相同内容；旧接口内部适配到
同一个 Fleet capability 安装调用，不再调用旧 create/bind/补偿执行器。
“相同内容”包括专家说明、成员和角色、技能原名/原文件字节、Connector 配置与绑定。
不表示两次无 key 的独立请求一定返回同一个已创建资源 ID。

这两个 HTTP 请求都没有客户端 `version_id` 字段。版本化安装开关开启后，版本由服务端
选取：根资源当前正式发布版本、该源快照内的依赖版本 pin。目标发布 v2 不会替换
源快照中的 v1；需要发布新的源版本才能改变 pin。相同 key 重试保持首次 plan，
包括当时的 Connector 配置；新 key 表示新操作。市场原名/文件不改写，同名不同
内容冲突返回 409，不通过自动改名安装多个版本。

保留两个内容适配器是为了支持已有数据格式：开关关闭时使用主干已有的内容读取，
开启版本化安装时使用正式 release/pin。执行器始终只有一个，且两条 URL 使用
相同开关。没有配置 capability installer 时都返回 503，绝不回落到另一套执行器。

本次评审修复同时收紧两个既有边界：卡片的每个已处理结果均保存不可变回执，
角色恢复或申请变化不会让旧事件重新执行（见[卡片回调契约](api/card-review-callback.md)）；
安装冲突仅展示固定安全文案，Fleet 任意消息不保留、不透传、不记录。

## 2. 上线前与灰度验收

1. **备份并盘点。** 备份数据库、对象存储、当前镜像和开关配置；在隔离副本运行
   [现有迁移工具](marketplace-stock-migration.md)的只读预览。分别记录已发布、
   下架、内嵌旧图、无正式版本、引用索引缺失资源。预览不是转换授权。
2. **核对 Fleet 部署。** 不需要更新旧客户端，但服务端 Fleet 必须已经提供当前
   capability installation 契约和幂等回执。先在测试工作区使用真实用户凭证分别
   调两条 URL；缺少服务端能力就停止灰度，不切回旧执行器。此 PR 不修改 Fleet。
3. **执行应用 schema。** 新增 `20261026-05-install-frozen-plans.sql` 是安装回执的
   增量字段；不修改既有迁移。先在副本演练备份恢复、Up 和重复 Up。Down 显式拒绝，
   避免丢失不确定安装的凭证。卡片回执另新增
   `20261027-01-card-terminal-receipts.sql`，仅解除回执对申请行的外键依赖，
   使不存在申请的最终拒绝也能持久化；先迁移再部署应用，保留原回执、主键与索引。
   此迁移同样禁止 Down；应用退回必须使用仍能重放全部终态回执的兼容镜像，
   否则暂停回调并向前修复，不删回执、不重新加回外键。部署前配置独立 `INSTALLATION_HMAC_KEY_ID` 和
   `INSTALLATION_HMAC_KEYS` 密钥环（活动 key 至少 32 字节），通过部署密钥注入，
   不放入日志或命令参数。轮换须保留旧 key，直到旧安装凭证不再需要重试。
4. **按数据就绪程度启用。** 现有 `PLUGIN_VERSION_MANAGEMENT_ENABLED`、
   `PLUGIN_REFERENCES_ENABLED`、`PLUGIN_PINNED_INSTALLATION_ENABLED` 的依赖顺序不变。
   开启最后一个开关前，实际要安装的资源必须具有独立引用、正式版本/pin及完整文件。
   没有完成转换的旧内嵌图会拒绝安装，不能仅打开开关后声称所有存量资源均已可安装。
   独立引用开关关闭时，删除直接检查存活来源的正式发布快照（含 Team 固定的旧成员版本），
   不要求回填新索引。开启独立引用后，删除保护要求现有引用索引完整；
   用 `cmd/marketplace-reference-index` 逐版本预览、
   核对 digest 后回填，不能关闭引用检查来绕过阻断。索引回填只读取历史关系，
   不抽取文件、不改写历史快照，也不要求把下架内容批量转换。
5. **对照验收。** 在隔离工作区分别验证 Expert/Team 两条 URL；检查内容和成员
   绑定而非只看 HTTP 200。补测下架/被引用删除、同 owner private 安装成功、
   跨 Space/不同 owner 拒绝、Fleet 403、超时原 key 重试及无 key 结果未知提示。

## 3. 下架历史与按需转换

下架数据在本次上线中不自动转换、不抽取内嵌技能、不重新上架，不改变旧版本和
发布指针。服务启动与安装请求均不会偷偷执行离线迁移。

当某个资源确实需要重新发布或安装时，由 owner/运维按以下顺序单独处理：

1. 在隔离副本对该 root 和所需依赖做只读预览，核对 owner、Space、visibility、
   文件完整性和版本映射。现有 CLI 仍会读取全量有界清单，`--root-id` 只限制写入
   目标，不代表只锁定该子图；必须使用受控维护窗口，不能在在线安装请求中调用。
2. 使用现有工具的 `--apply --root-id ROOT_ID --expected-digest DIGEST --batch-id ...`
   明确转换这一个根，按技能/成员/团依赖顺序处理。命令和必要前置条件见
   [迁移工具说明](marketplace-stock-migration.md)。有异常时停止，不猜版本或放宽
   private 权限。工具不支持安全转换的形态保持原状，先修复数据/工具再重试。
3. 转换保留下架状态。owner 核对后按正常发布流程逐个恢复需要的依赖与来源；Admin
   沿用主干已有直接生效规则，不新增审核。根仍下架、依赖下架或缺少正式版本/pin
   时，不允许新安装。只有整个图满足发布与访问规则后，才重新尝试安装。

历史记录可以阅读，不等于获得新安装豁免。纯历史快照不锁住无引用资源，但活跃
下架来源的现存引用仍参与删除保护；需要先通过正常编辑/重新发布移除引用。

## 4. 超时、故障与恢复

- **带 key 的结果未知：** 保留首次 key、原参数和环境变量，在响应 `retry_until`
  之前重试；plan 不重新解析新版。未开启版本化安装时没有本地 `retry_until`，
  沿用 Fleet 的首次请求 24 小时幂等窗口，不把每次重试当成新窗口；旧内容模式
  不承诺冻结 plan。每次仍检查当前资源权限，并向 Fleet 验证工作区
  权限；不直接从本地成功回执返回资源。不要跨接口更换 key。只有输入确实相同且
  有同一个 key 的新旧入口才能关联到同一操作。
- **旧客户端没有 key：** 每次请求是新操作，网络超时后无法保证自动去重。先在
  工作区核对资源，再决定是否重试；错误提示不会宣称可以使用原 key 自动重放。两种内容模式下，网络超时、Fleet 5xx
  或空结果均视为结果未知；408、通用/未知/处理中的 409 仍保持未知。已识别的
  重复/幂等键冲突，以及带明确技能/专家/团资源类型的内容冲突，保留 409、
  固定中文安全文案与安全原因字段（不透传 Fleet 原文）；
  429 保留 `RATE_LIMITED` 和合法的 `Retry-After`，等待后可在原期限内以原 key、
  原请求重试。版本化安装已记录过结果未知时，后续明确拒绝不会抹掉该历史。
  后续客户端可选传稳定 key，不影响没有升级的客户端正常安装。
- **凭证过期或旧 schema 凭证没有 frozen plan：** 不再重发可能重复创建的请求。
  先核对 Fleet 工作区已有资源，再用新 key。保留安装尝试记录供排查；不清表。
- **线上缺陷：** 暂停新的安装/发布写入，记录 request ID、安装 attempt ID、
  资源/版本 ID、镜像与开关；不记录 token、custom_env、正文或密钥。对照 Fleet
  与本地回执确认是否已创建，优先向前修复并在副本复现。
- **需要退回应用：** 仅回退到已验证可读取新增字段、仍使用同一原名字节和幂等
  key 算法的兼容镜像；未验证兼容时继续暂停写入并向前修复。不能简单关闭开关
  后重新发起旧安装，更不能直接恢复旧指针。已经执行过单 root 转换时，先保存
  批次证据，在副本按现有迁移工具的并发漂移检查演练恢复；有发布或新引用变化
  则停止恢复、向前修复。不可在本次安装恢复中运行 SQL Down 或清理历史证据。

## 5. 验证范围

代码验证覆盖两条入口的完整 Fleet 请求等价、旧式参数、private 双层关系、
直接/间接删除保护、纯历史保留、超时/租约/密钥轮换、权限撤销和失败关闭。
评审回归另覆盖终态拒绝重放、并发事件唯一胜出、审批与回执原子回滚、临时故障重试，
以及新旧安装入口的固定文案和响应/日志不泄露上游原文；迁移验证重复执行与禁止 Down。
上线前仍需针对实际 Fleet 部署与真实旧客户端做受控验收；本地模拟不能代替此项。
