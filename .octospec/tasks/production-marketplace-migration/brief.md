# Marketplace single-database migration
Goal: convert the current existing database in place, using one MYSQL_DSN. Copying production data to test is separate environment preparation.
Load-bearing: restore missing Skill descriptions from intact original frontmatter or explicit hash-bound operator catalog metadata; never auto-promote body prose; preserve independently split drafts without formal dependencies; canonicalize complete equivalent same-scope/owner/lifecycle MCP resources; suffix retained same-name connectors only within overlapping installation closures without changing MCP values or supporting bytes; namespace colliding MCP server keys by source while freezing original documents and revalidating exact key-only projections; normalize MIME and Windows ZIP separators without changing source bytes; platform/Space/owner isolation, agreed duplicate policy, full file bytes, valid releases and fixed references, stable IDs, transactional receipts and same-run resume, immutable history, safe error reporting.
Scope: Go command/core/tests/docs plus the required platform attachment ownership support in Marketplace. No database export/restore, schema upgrade, deployment, feature-gate removal or cross-database copying.
Acceptance: planner negative isolation cases; database binding; private checkpoint integrity; object digest and ownership; conversion and retry tests; full Go test/vet/build. Real MySQL and test environment runs must be reported separately when actually executed.
Operator guide: docs/production-marketplace-migration.md.

COS compatibility: canonical COS API endpoints use the signed native forbid-overwrite header instead of S3 If-None-Match. Before immutable writes, fail closed unless bucket versioning can be read and is unset; never change bucket settings. Handle only COS FileAlreadyExists as reusable, leaving content verification mandatory. Regression coverage must include signed requests, preserved bytes, versioning/permission failures and unchanged S3 behavior. No production data migration or deployment is part of this fix.

Decision for the replacement in-place migration: preserve existing MCP endpoint, authentication and extension configuration as requested, superseding the retired backfill sanitizer. Existing literal values remain readable to the source resource's authorized audience; this is not a secret-reference conversion or a claim that credentials are absent. Extracted connectors must retain the source owner/Space/visibility/listing boundary; private checkpoint/report rules still apply. Persisted-package and system/Space/private read-audience regressions cover this decision.
Managed scalar icons retain the proven global upload namespace independently of resource IDs, with frozen bytes, source digest/size evidence and final object inspection. External icon URLs are preserved but not fetched. Checkpoint v8 requires complete Connector equivalence and the evidence contract and rejects prior format versions.
